# Output catalogue

Every file under `output/` is generated by `scripts/update.py`. Nothing here is hand-edited,
and every listed config passed a real proxied request through Xray during the run that
produced it.

**Bases**

```
raw     https://raw.githubusercontent.com/noahclanman/free-xray-gcp/main/output
mirror  https://cdn.jsdelivr.net/gh/noahclanman/free-xray-gcp@main/output
```

`raw` is served with a short cache (~5 min), jsDelivr with a long one (~12 h). Prefer `raw`.

---

## 1. Collections

| Path | Contents | Subscribe | Sorted by |
|---|---|---|---|
| `all/configs.txt` | every verified config | yes | Asia → GCP → latency |
| `all/configs_base64.txt` | same, base64 subscription | **yes** | – |
| `gcp/configs.txt` | configs whose server IP is in Google Cloud | yes | latency |
| `gcp/configs_base64.txt` | same, base64 | **yes** | – |
| `fast/configs.txt` | configs at or under `FAST_MS` (default 400 ms) | yes | latency |
| `fast/configs_base64.txt` | same, base64 | **yes** | – |
| `top100.txt` | the 100 fastest configs | yes | latency |

`configs.txt` files start with `#profile-*` comment headers (title, update interval,
web page). Subscription clients ignore them; a plain base64 blob is in the twin file.

**`gcp/` only exists when at least one GCP config passed the test.** The pool is small, so
some runs publish no GCP folder at all. In that case `index.json` reports
`categories.gcp.count = 0` and `files` is `null` — that is not a broken build.

## 2. Protocols — `protocols/`

| File | Protocol |
|---|---|
| `vless.txt` / `vless_base64.txt` | VLESS (incl. Reality and XTLS flows) |
| `vmess.txt` / `vmess_base64.txt` | VMess |
| `trojan.txt` / `trojan_base64.txt` | Trojan |
| `shadowsocks.txt` / `shadowsocks_base64.txt` | Shadowsocks |

Files are only written when they contain at least one config.

## 3. Transports and security — `transports/`

Two naming axes: **transport** (how bytes are framed) and **security** (how the stream is
protected). A file named `<transport>_<security>.txt` contains only that combination.

| Transport | Meaning |
|---|---|
| `tcp` | plain TCP (Xray `raw` is normalised to `tcp`) |
| `ws` | WebSocket |
| `grpc` | gRPC / gun |
| `http` | HTTP/2 (h2) |
| `xhttp` | XHTTP / split-http |
| `httpupgrade` | HTTPUpgrade |
| `kcp` / `quic` | mKCP / QUIC (rare in free lists) |

| File | Contents |
|---|---|
| `tls.txt` | everything wrapped in TLS, any transport |
| `reality.txt` | everything using Reality |
| `non_tls.txt` | no TLS layer at all (plain VMess, Shadowsocks, ...) |
| `ws_tls.txt` | WebSocket over TLS — the most compatible kind |
| `grpc_tls.txt` | gRPC over TLS |
| `xhttp_tls.txt` | XHTTP over TLS |
| `httpupgrade_tls.txt` | HTTPUpgrade over TLS |
| `http_tls.txt` | HTTP/2 over TLS |
| `tcp_tls.txt` | TLS directly over TCP (no CDN-friendly framing) |
| `<transport>_reality.txt` | Reality variants (usually `tcp_reality`, `grpc_reality`, `xhttp_reality`) |

Only combinations that currently have configs are written. Each has a `_base64.txt` twin.

## 4. Countries — `Countries/`

One plain-text file per country, named with the English country name and underscores
(`United_States.txt`, `The_Netherlands.txt`, `Hong_Kong.txt`), sorted by latency.
Country is resolved from the **server IP** with DB-IP Country Lite, not from the remark,
so it cannot be spoofed by whoever made the config.

`Countries/index.json`:

```json
{
  "generated_at": "2026-10-20T14:26:11Z",
  "source": "all",
  "criterion": "passed a real proxied request through xray",
  "location_method": "GeoIP (DB-IP Country Lite)",
  "countries": [
    { "code": "CA", "name": "Canada", "flag": "🇨🇦",
      "region": "North America", "count": 18,
      "file": "Countries/Canada.txt" }
  ]
}
```

Country files are browse-only (no base64 twin) because they are not meant to be used as
subscriptions. Use `all/` or `regions/` for that.

## 5. Regions — `regions/`

`Asia.txt`, `Europe.txt`, `North_America.txt`, `South_America.txt`, `Africa.txt`,
`Oceania.txt`, `Other.txt`. Asia is listed first in the main collection.

## 6. Naming scheme

```
JP 🇯🇵 | 288ms | 1d974
GCP SG 🇸🇬 | 402ms | 3ae49
```

| Part | Meaning |
|---|---|
| `GCP ` | optional prefix: the server IP belongs to Google Cloud |
| `JP 🇯🇵` | ISO country code + flag, from the server IP |
| `288ms` | real proxy round trip from the GitHub runner |
| `1d974` | first 5 hex chars of `sha1(server + credentials)` — stable ID |

The hash lets clients keep a selection across refreshes even though remarks change with
latency. Duplicate configs (same server, same credentials, different remark) are removed.

## 8. `health.json`

Written on every successful run, useful for monitoring:

```json
{
  "status": "ok",
  "updated_at": "2026-10-20T14:26:11Z",
  "duration_seconds": 842.5,
  "xray": "Xray 26.3.27 ...",
  "geoip": "db-ip country lite",
  "sources": { "active": 20, "failed": [] },
  "counts": {
    "links_collected": 42351, "unique": 17473, "on_gcp": 10,
    "tcp_reachable": 10156, "tested": 3300, "working": 640, "published": 640
  }
}
```

A failed run does not write `health.json`; the previous output is left in place and the
workflow run turns red.

## 9. Update cadence

| | |
|---|---|
| Schedule | every 30 minutes (`cron: */30 * * * *`) |
| Manual | Actions → *Update GCP V2ray configs* → Run workflow |
| Time budget | 20 min of real testing, 45 min job limit |
| On zero working configs | previous `output/` kept, run fails |
| Cache | raw ≈ 5 min, jsDelivr ≈ 12 h |
