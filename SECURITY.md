# Security policy

## What this repository is

A **public aggregator of configuration links** that other people published, plus the script
that tests them. It does not run, rent or operate any proxy server. The configs are
third-party infrastructure and come with no trust guarantee of any kind.

## Reporting a vulnerability

If you find a security problem **in this repository's own code** — the Python script, the
GitHub Actions workflow, the way tokens or permissions are used, a way to make the bot publish
attacker-controlled data, or a supply-chain issue — please report it privately:

- **GitHub Security Advisory** — *Security* tab → *Report a vulnerability* (preferred), or
- **Telegram** — [@xray_ehi_hub](https://t.me/xray_ehi_hub) (direct message).

Please include the affected file, the impact, and reproduction steps if you have them.

**Do not open a public issue for a vulnerability.** You will get an acknowledgement within a
few days. There is no bug bounty, but credit is given in the fix commit if you want it.

## Out of scope

These are known and expected, not vulnerabilities:

| Report | Why it is out of scope |
|---|---|
| "This proxy server is dead" | Free configs die constantly; the list is rebuilt every 30 minutes |
| "This proxy sees my traffic" | Inherent to using someone else's server — never send sensitive traffic |
| "This config is malicious / logs me" | We test reachability, not the operator's intentions |
| "The list contains a bad remark" | Remarks are generated by us; a weird one is a bug, not a vuln — open an issue |
| Third-party badge or QR image does not load | Cosmetic; the URLs are always printed in text |

## Safe usage

- **Assume the operator can see your traffic metadata** (destination, timing, volume) and may
  log it. Use TLS inside the tunnel for anything you care about.
- **Do not use free configs for banking, email, work accounts or identity logins.**
- **Consider the law where you live.** This project takes no position on what you do with it.
- **Keep your client updated.** Old Xray/v2ray cores have their own vulnerabilities.
- **Never paste a private key or token into an issue.** Subscription URLs are public by design;
  credentials in your own configs are not.

## For forks

If you run your own copy:

- Keep the workflow's permission at **Read and write** only for `contents` — that is all it needs.
- Do not add repository secrets to the workflow; it requires none.
- Pin third-party actions if you modify them (the default workflow uses `actions/checkout@v4`
  and `actions/setup-python@v5` only).
- The Xray binary is downloaded from the official `XTLS/Xray-core` release page at run time. If
  you want reproducibility, pin a release tag instead of `latest`.

## Supported versions

Only the `main` branch is maintained. Old commits, forks and archived copies are not patched.
